# 🔧 Исправление ошибки 404

## Проблема

При деплое на GitHub Pages возникает ошибка:
```
Failed to load resource: the server responded with a status of 404 ()
```

## Причина

GitHub Pages - это статический хостинг. Когда вы открываете URL вроде:
```
https://username.github.io/repo-name/some/path
```

GitHub Pages ищет файл `/some/path` в вашем репозитории. Если файла нет, он возвращает 404.

Но ваше приложение - это SPA (Single Page Application). Все маршруты обрабатываются на клиенте через JavaScript. Поэтому нужен способ сказать GitHub Pages: "Не ищи файлы, просто отдай index.html".

## Решение

### 1. Относительные пути в Vite

В `vite.config.js` добавлен параметр:
```javascript
base: "./"
```

Это заставляет Vite генерировать относительные пути к ассетам:
- ❌ Было: `/assets/index-abc123.js`
- ✅ Стало: `./assets/index-abc123.js`

Теперь приложение работает независимо от того, в какой поддиректории оно находится.

### 2. 404.html для SPA routing

Создан файл `public/404.html` со специальным скриптом.

**Как это работает:**

1. Пользователь открывает: `https://username.github.io/repo-name/dashboard`
2. GitHub Pages не находит файл `/dashboard` и возвращает `404.html`
3. Скрипт в `404.html` преобразует URL в:
   ```
   https://username.github.io/repo-name/?/dashboard
   ```
4. Браузер загружает `index.html` (который теперь существует)
5. Скрипт в `index.html` восстанавливает правильный URL:
   ```
   https://username.github.io/repo-name/dashboard
   ```
6. React Router видит правильный URL и показывает нужную страницу

### 3. Копирование 404.html при деплое

В `.github/workflows/deploy.yml` добавлен шаг:
```yaml
- name: Copy 404.html for SPA routing
  run: cp dist/index.html dist/404.html
```

Это создаёт копию `index.html` как `404.html` в папке `dist/`.

## Проверка

### Локально

```bash
# Соберите приложение
npm run build

# Проверьте что dist/404.html существует
ls -la dist/404.html

# Запустите preview
npm run preview
```

Откройте http://localhost:4173 и проверьте что всё работает.

### На GitHub Pages

После деплоя откройте:
```
https://username.github.io/repo-name/
```

Попробуйте обновить страницу (F5) - она должна загрузиться без ошибки 404.

## Альтернативные решения

### Если не хотите использовать 404.html

Можно использовать hash-based routing в React Router:

```javascript
// Вместо BrowserRouter
import { HashRouter } from 'react-router-dom';

<HashRouter>
  <App />
</HashRouter>
```

URL будут выглядеть так:
```
https://username.github.io/repo-name/#/dashboard
```

**Плюсы:**
- Не нужен 404.html
- Работает на любом статическом хостинге

**Минусы:**
- URL выглядят менее красиво
- Не работают якоря (anchors)

### Если используете другой хостинг

#### Vercel
Создайте `vercel.json`:
```json
{
  "rewrites": [
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}
```

#### Netlify
Создайте `netlify.toml`:
```toml
[[redirects]]
  from = "/*"
  to = "/index.html"
  status = 200
```

#### Nginx
```nginx
location / {
  try_files $uri $uri/ /index.html;
}
```

#### Apache
Создайте `.htaccess`:
```apache
RewriteEngine On
RewriteBase /
RewriteRule ^index\.html$ - [L]
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule . /index.html [L]
```

## Troubleshooting

### Проблема: 404 всё ещё появляется

**Решение 1:** Очистите кэш GitHub Pages
```bash
# Добавьте пустой коммит
git commit --allow-empty -m "Clear GitHub Pages cache"
git push
```

**Решение 2:** Проверьте что 404.html загружается
1. Откройте DevTools (F12)
2. Вкладка Network
3. Обновите страницу
4. Найдите запрос к 404.html
5. Проверьте что он возвращает 200 OK

**Решение 3:** Проверьте base path
```bash
# Проверьте vite.config.js
cat vite.config.js | grep base
```

Должно быть: `base: "./"`

### Проблема: Стили не загружаются

**Причина:** Неправильные пути к ассетам

**Решение:**
1. Проверьте `vite.config.js` - должен быть `base: "./"`
2. Пересоберите приложение: `npm run build`
3. Проверьте `dist/index.html` - пути должны быть относительными:
   ```html
   <script type="module" crossorigin src="./assets/index-abc123.js"></script>
   ```

### Проблема: Редирект не работает

**Причина:** Скрипт в 404.html не выполняется

**Решение:**
1. Откройте DevTools (F12)
2. Вкладка Console
3. Проверьте что нет ошибок JavaScript
4. Проверьте что скрипт в 404.html выполняется
